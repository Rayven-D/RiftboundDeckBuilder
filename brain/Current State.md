## Product (ADR-0006)
Product name: **Rift Builder** (was "Riftbound Deck Builder", briefly "Rift Decks"). Tabs: **Decks**, **Collection**, **Tournaments** and a home page at `/`. **Header change decided (RJ 2026-11-24, [[ADR-0006 Two Imports - Collection and Decks]], not built yet):** the Import button becomes the account (username top right: account settings with Change username, Theme per device defaulting to system, Delete account and data, Sign out); collection import becomes **"Add to your collection"** (FAB bottom right on Collection), deck import stays **"Import deck"** on Decks, both as dialogs; `/import` is removed. Spec H-174, brief H-175, build H-176.
- **Collection:** cards the user owns, from **Owned Cards Import**. Every printing is its own
  entry with a count badge. Tags go on printings, and a tag can be marked "exclude from decks".
  Default order is set → collector number.
- **Decks:** community decks from **Deck Import**, or "Add to your decks" from Tournaments.
  Cards are grouped by name and expand to show owned printings. Decks share one pool of physical cards;
  a complete deck can be **locked in** so other decks stop counting its copies. **Runes are cards like any
  other** (RJ, 2026-11-24: imported, counted, shared and locked; SPEC-009 withdrawn, build H-098). Available cards are in full colour,
  missing ones darkened, partly owned ones filled left to right (1 of 3 → ⅓). Ban status is shown on
  every card.
- **Tournaments:** recent events, Top 8 with published placings. Its job is a source of winning constructed decks to add as a goal (RJ, 2026-11-23), not a feature of its own. No meta statistics, ever (ADR-0003).
- **Account required to import (RJ 2026-11-24, [[Accounts and Sync]] v0.8, [[ADR-0007 Firebase Accounts and Firestore]] amendment accepted):** importing cards or decks needs an account; Tournaments and Home need none; signed out, Tournaments shows no "Add to your decks"; sign-out clears the device; first sign-in clears old browser data, then downloads. Built in H-081 (validator PASS), on `loop/SPEC-010-v0.9-build` with the rest of the chain. Production keeps no-account imports until sign-in is turned on.
- **Account-only (RJ 2026-11-24, [[ADR-0007 Firebase Accounts and Firestore]] amendment 2):** local-only mode is dropped. All user data lives in the signed-in account (Firestore); the browser only caches it for speed (session, recently viewed cards and decks); deleting the account deletes everything. Card and deck lists scroll smoothly with no pagination. Spec H-171, build H-172, scrolling brief H-173. Production stays on its current build until sign-in is ready there (H-063, H-152, Firestore rules).
- **Constraints:** free; storage is account-only since SPEC-010 0.12 (H-171; code still two-mode until H-172) (ADR-0007 amendment): `signInEnabled: false` (production today) = browser storage only, no accounts; `signInEnabled: true` = account required to import, browser is a cache of the account. Riot API is
  the only card data source, no Riot logos, key server-side only, Riot data only (no curated alias or date tables).
