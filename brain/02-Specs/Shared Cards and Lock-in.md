# SPEC-008: Shared Cards and Lock-in

## Summary
- **"Can't lock" notice (v0.7, H-670, RJ 2026-11-26, chat):** pressing the lock toggle on a deck that is not complete locks nothing and shows "Can't lock. Missing `<x>` cards." (`x` = the deck's missing copies, RJ's choice; "1 card"); pressing "Lock these copies" on a name that is not fully available shows "Can't lock. Missing `<x>` copies." ("1 copy"). The visible reason line "Lock in needs every card available: n cards short" is removed ("Remove it to save space"); the string stays as hidden screen-reader text (SHARE-020, SHARE-096). The apostrophe and the final period are builder formatting, not RJ's typing. Notices open at the top of the page (SPEC-010 SYNC-161).
- **v0.8 (H-674, H-675, RJ 2026-11-26, chat, multiple choice):** (1) **RJ approved the card-name lock wording "as built"** ("Approve as built"): the removal dialog (title "Unlock cards in your decks?", intro, per-deck lines, "'`<deck>`' will no longer be locked.", button "Unlock and continue"), the sync notice "Locks removed after a change on another device." with its per-deck lines, the card dialog buttons "Lock these copies" / "Unlock these copies", and the auto-lock and partial-unlock snack bars (SHARE-029, 088, 091, 094; Open questions 8 (a), 9 (labels and snack bars), 14 closed). (2) **Other lock-blocking reasons now show a notice** ("Yes, show a notice", Open question 17 closed): pressing the deck toggle or the card-name Lock control while it is blocked for read-only, locks unreadable, ownership unavailable or no cards shows "Can't lock. " followed by that reason's existing sentence; a save in progress shows nothing (new SHARE-097, ACs 40, 41). The exact strings come from existing text and are builder defaults for RJ to confirm.
> Read this first. Full detail below only if needed.

**v0.6 (H-664, RJ 2026-11-26, in chat) changes the lock model. Read this block first; where it conflicts with the older Key rules below, v0.6 wins (the older bullets are marked "v0.6:" where they changed).**
- **The lock is now per card name, per deck (section I, SHARE-080…095).** A **name lock** (deck, `cardKey`) reserves that deck's required copies of the name from the shared pool, so other decks can't count them. It is allowed only when the name is **fully satisfied** for that deck (every required copy available, "fully coloured in"; SHARE-081). It is independent of the deck's own lock status.
- **The deck lock is derived:** a deck is locked **exactly when every card name in it has a name lock** (SHARE-083). The last name lock locks the deck automatically; the deck lock toggle (H-662) locks every name at once and unlocking a locked deck removes **only that deck's** name locks (SHARE-084). Unlocking one name of a locked deck leaves the deck not locked and its other names locked (SHARE-085; RJ 2026-11-26, chat, Open question 7 resolved).
- **A locked name is never short.** The "Locked · n cards short" state, the "stays locked and flagged" rule and the "will be n cards short" warnings are **removed** (SHARE-033, SHARE-034, SHARE-050 rewritten). Replaced by: **removing copies takes free copies first; only if that would drop a lock below its deck's need does a confirmation list the decks and names it unlocks** (SHARE-087…090). A change from another device that leaves a locked name short **unlocks it with one combined notice, no dialog** (SHARE-091, replaces SYNC-074).
- **Storage:** `StoredDeckLocks` `schemaVersion: 2`, entries per (deck, name); a v1 deck lock migrates to a lock on every name of the deck (SHARE-092). The Firestore `state/locks` document changes shape (SPEC-010 SYNC-017).
- **UI:** the per-name Lock / Unlock control is in the **card dialog only**; Deck detail tiles and rows show only a small lock icon for a locked name, no other text (SHARE-094).

**Purpose:** a user's decks draw on one physical collection. Every deck shows which of its cards other
decks also use (which decks, how many each needs). A **complete** deck can be **locked in**: its copies
then stop counting toward any other deck until it is unlocked or deleted (RJ, ADR-0006 "Shared cards, lock
in and runes").

## Purpose
Users import several community decks they want to build ([[ADR-0006 Two Imports - Collection and Decks]]).
They often share cards: two Kennen decks need the same Legend, the same signature spells, the same
battlefields. A physical card can only sit in one assembled deck at a time ([[Physical Copies Across Decks]]
facts 6, 7), so the app must show where copies are contested, and let the user commit copies to one deck
("lock in") so other decks stop counting them.

This spec owns the cross-deck pool, the lock rules and their storage, and the shared-card display content.
SPEC-005 owns the deck view and tiles and reads this spec's `SharedPool`. Runes have no rule of their own
(SHARE-006; SPEC-009 was withdrawn on 2026-11-24).

## Definitions
- **Deck**: a SPEC-006 `UserDeck` in the `DeckStore` (DECK-090).
- **Counted zone**: `legend`, `champion`, `main`, `battlefields`, `runes`, `sideboard` (`COUNTED_ZONES` =
  the SPEC-005 `ZONE_ORDER`, v0.4; v0.3 left out `runes`).
- **Counted entry**: any `DeckCard` in a counted zone, so every entry of the deck (v0.4; v0.3 left out
  rune entries, SPEC-009 RUNE-001, withdrawn).
- **cardKey / pool key**: SPEC-001 `cardKey` = `nameKey(canonical name)` (CARD-012). All printings and
  variants of a name share it (CARD-013).
- **need(D, k)**: Σ `qty` of `k` over D's counted entries (= SPEC-005 card required, OWN-021).
- **User of k**: a deck with need(D, k) ≥ 1.
- **ownedForDecks(k)**, **ownedExcluded(k)**: from SPEC-007 `deckOwnership(input, k)` (COLL-081); 0 for an
  unknown card (SPEC-005 OWN-061).
- **Name lock** (v0.6): a `NameLock { deckId, cardKey, lockedAt }` in the `DeckLockStore`: deck D has locked its copies of name k (SHARE-080).
- **Locked deck** (v0.6, derived): a deck with at least one counted entry in which **every** counted `cardKey` has a name lock (SHARE-083). A deck with some but not all names locked is **partly locked**, which is not locked. **Lock order**: name locks sorted by `lockedAt` ascending, then `deckId`, then `cardKey`; it only settles conflicts (SHARE-032, SHARE-090).
- **hold(L, k)** (v0.6): need(L, k) when L has a name lock on k, else 0 (SHARE-031).
- **lockedByOthers(D, k)**: Σ hold(L, k) over decks L ≠ D.
- **available(D, k)**: max(0, ownedForDecks(k) − lockedByOthers(D, k)).
- **free(k)** (v0.6): ownedForDecks(k) − Σ hold over all decks: the copies no lock holds (SHARE-087).
- **Complete deck**: SHARE-014. ~~Short locked deck~~ (SHARE-033 withdrawn in v0.6).
- **Now**: the current time, an input to locking only (`lockedAt`). The pool computation reads no clock.

## Design decisions (summary)
1. **Every physical section counts, runes too** (RJ, ADR-0006; runes added by RJ on 2026-11-24: "Allow
   users to import runes as well and treat them like any other card."). Legend, Battlefield and Rune cards
   are not Main Deck cards, but each assembled deck needs its own physical copies (facts 6, 7, 10), so they
   compete across decks like any card. Chosen Champion, Main Deck and Sideboard copies of one name are one
   pool (facts 2, 3, 8). Rune names have no per-name limit (fact 10), so one deck can need 9 or 12 of one.
2. **Pool per card name, not per printing.** The deck rules count names (fact 2, fact 14), decks store only
   `cardKey`s (DECK-096), and SPEC-007 already gives one per-name number (`ownedForDecks`) from its
   per-printing Collection. So this spec never looks at printings, and the "exclude from decks" tag applies
   before any lock.
3. **Earliest lock wins** (Claude default, accepted by RJ 2026-11-23). When locked decks together need more than the user owns (after a
   re-import or edit), the deck locked first keeps its copies. Any fixed rule works; this one never takes
   copies from a deck that was complete when the user locked a newer one.
4. **A lock never yields to an unlocked deck** (Claude default, accepted by RJ 2026-11-23). That is the point of locking.
5. **~~Short locked decks stay locked~~ (reversed in v0.6, RJ 2026-11-26).** A name lock can only exist while the name is fully held; when a collection change would leave it short, the lock is dropped after the user confirms (or, for a change from another device, with a notice). A locked name is never short and there is no "cards short" flag.
6. **No card edits while locked (Claude default, accepted by RJ 2026-11-23); Undo restores the deck still locked (reversed in v0.7, RJ 2026-11-26, chat, "Yes, keep its locks"; the earlier default "Undo restores unlocked" is withdrawn).** Editing could silently grow a
   lock's hold and push a later lock short. *(Withdrawn reasoning: restoring a deleted deck's old lock time could take copies from a
   deck locked during the Undo window. Now the restored deck's older locks win, SHARE-024 (c).)* **The name, description and source are not cards** (v0.4.5, RJ 2026-11-25:
   "All deck names can be changed by the user at any time"): they stay editable while locked, because they change
   no need, hold or lock order.
7. **Only the lock is stored.** Holds, availability and shortfall are computed from (decks, locks,
   collection, tags) every time, like SPEC-005 ownership (OWN-026).

## Data contract
```ts
// shapes only; no implementation
import type { UserDeck, DeckZone } from './deck-import';                  // SPEC-006 v0.16.1
import type { DeckOwnershipInput } from './my-collection';              // SPEC-007 v0.11, COLL-081
type CardKey = string;
type IsoDateTime = string;                                              // ISO 8601 UTC

// Counted zones: every zone, = SPEC-005 ZONE_ORDER (SHARE-001, SHARE-006; v0.4 added 'runes').
const COUNTED_ZONES: DeckZone[] = ['legend', 'champion', 'main', 'battlefields', 'runes', 'sideboard'];

// ---- Stored (SHARE-060..065; v0.6 = SHARE-080..092) ----
interface NameLock {              // v0.6: replaces DeckLock { deckId, lockedAt }
  deckId: string;                 // UserDeck.id
  cardKey: CardKey;               // the name locked in that deck
  lockedAt: IsoDateTime;          // lock order key (SHARE-030); never displayed
}
interface StoredDeckLocks {
  schemaVersion: 2;               // v1 = [{ deckId, lockedAt }], migrated on load (SHARE-092)
  updatedAt: IsoDateTime;
  locks: NameLock[];              // at most one per (deckId, cardKey) (SHARE-022); orphans dropped on save (SHARE-062)
}
interface DeckLockStore {         // adapter: the browser cache of the account's locks (SHARE-060)
  load(): Promise<StoredDeckLocks | null>;   // throws / reports unreadable or newer → SHARE-061
  save(l: StoredDeckLocks): Promise<void>;
}

// ---- Computed (never stored, SHARE-035) ----
interface SharedPoolInput {
  decks: UserDeck[];                         // every deck in the DeckStore (SHARE-005)
  locks: NameLock[] | null;                  // null = lock store unreadable → all locks ignored (SHARE-061)
  ownership: DeckOwnershipInput;             // SPEC-007
}

interface CardUse {                          // one deck using one card (SHARE-015)
  deckId: string;
  deckName: string;
  need: number;                              // need(D, k), counted zones only
  locked: boolean;                           // v0.6: this deck's name lock on k (not the deck lock)
  hold: number;                              // hold(D, k); 0 when the name is not locked
}

interface CardPool {
  cardKey: CardKey;
  ownedForDecks: number;                     // COLL-081; 0 for an unknown card
  ownedExcluded: number;                     // COLL-081; never available
  heldTotal: number;                         // Σ hold over name locks; ≤ ownedForDecks (SHARE-031)
  free: number;                              // v0.6: ownedForDecks − heldTotal (SHARE-087)
  uses: CardUse[];                           // every user of k, SHARE-015 order
}

interface DeckLockState {
  deckId: string;
  locked: boolean;                           // v0.6: every counted cardKey has a name lock (SHARE-083)
  lockedAt: IsoDateTime | null;              // v0.6: latest name `lockedAt` of a locked deck, else null; internal, never shown
  lockedNames: CardKey[];                    // v0.6: counted cardKeys with a name lock (partly locked: some, not all)
  complete: boolean;                         // SHARE-014
  // v0.6: `short` and `cardsShort` are removed (SHARE-033 withdrawn)
}

interface SharedPool {
  locksIgnored: boolean;                     // true when input.locks === null (SHARE-061)
  byCard: Record<CardKey, CardPool>;         // counted cardKeys of all decks
  byDeck: Record<string, DeckLockState>;
}

interface CardAvailability {                 // what one deck sees for one card (SHARE-043)
  deckId: string;
  cardKey: CardKey;
  ownedForDecks: number;                     // X
  ownedExcluded: number;                     // E
  lockedByOthers: number;                    // Y (SHARE-010)
  available: number;                         // Z = max(0, X − Y) (SHARE-011)
  need: number;                              // N
  heldByThisDeck: number | null;             // H when this deck has a name lock on k (v0.6), null otherwise
  nameLocked: boolean;                       // v0.6: this deck has a name lock on k (drives the lock icon, SHARE-094)
  otherUses: CardUse[];                      // SHARE-015, without this deck
}

type LockCheck =                            // first failing check wins (SHARE-020):
  | { ok: true }                             // already-locked → read-only → locks-unreadable →
  | { ok: false; reason: 'already-locked' | 'no-cards' | 'incomplete' | 'ownership-unavailable'
                       | 'locks-unreadable' | 'read-only'; cardsShort?: number };
                                             // ownership-unavailable → no-cards → incomplete;
                                             // cardsShort only with 'incomplete'; message per SHARE-020

// computeSharedPool(input: SharedPoolInput): SharedPool                       — pure (SHARE-070)
// availability(pool: SharedPool, deckId: string, cardKey: CardKey): CardAvailability — pure
//   a cardKey not in pool.byCard (no deck uses it) gets all zeros; since v0.4 rune cards are in byCard
// canLock(pool: SharedPool | null, deck: UserDeck, readOnly: boolean, isLocked: boolean): LockCheck — pure;
//   pool null = ownership unavailable (OWN-062/063); isLocked = the deck has a DeckLock in a readable
//   lock store (v0.4.2, SHARE-020), so 'already-locked' also works with a null pool
// v0.6 (replaces lockedShortfalls, SHARE-034 withdrawn):
type NameLockCheck =                        // first failing check wins (SHARE-081)
  | { ok: true }
  | { ok: false; reason: 'already-locked' | 'read-only' | 'locks-unreadable' | 'ownership-unavailable'
                       | 'not-in-deck' | 'not-full'; available?: number; need?: number };
interface LockLoss {                         // one name lock that SHARE-090 drops
  deckId: string; deckName: string;
  cardKey: CardKey; cardName: string;
  copies: number;                            // hold(D, k) lost = the deck's need of that name
  deckUnlocks: boolean;                      // the deck was locked and stops being so (SHARE-083)
}
// canLockName(pool: SharedPool | null, deck: UserDeck, cardKey: CardKey, readOnly: boolean,
//             isNameLocked: boolean): NameLockCheck                              — pure (SHARE-081)
// lockLosses(before: SharedPool, after: SharedPool): LockLoss[]                  — pure (SHARE-087…090)
//   `after` is the pool for the collection as it would be after the change (Replace import, Undo of an
//   import: the snapshot it would restore, edits, an exclude flag) computed BEFORE it is committed; the
//   result lists the name locks SHARE-090 drops, latest lock first, and is empty when free copies cover
//   the change (no dialog). The same function with the merged state gives the SHARE-091 notice
// settleLocks(locks: NameLock[], ownedForDecks: (k) => number, decks: UserDeck[]): NameLock[]
//   — pure; the locks to keep after SHARE-090 (the Σ hold ≤ ownedForDecks invariant)
// migrateLocksV1(v1: { deckId; lockedAt }[], decks, collection input): StoredDeckLocks — pure (SHARE-092)
// With ownership unavailable (SHARE-053) the caller builds DeckLockState from the stored name locks:
//   { deckId, locked: true, lockedAt, lockedNames, complete: false } when every counted name is locked, else null
```

## Out of scope
- Sharing decks with other people. *(Accounts and syncing locks between a user's own browsers were out of scope
  until v0.4; since v0.4.1 they are specified in [[Accounts and Sync]] SPEC-010.)*
- Reserving a specific printing for a deck ("lock my foil into this deck"): decks stay by `cardKey` (DECK-096).
- Lock priorities the user sets, or automatic suggestions of which deck to lock. *(v0.5 also listed "partial locks (locking some cards of a deck)" here; since v0.6 they are in scope as name locks, SHARE-080.)*
- Reserving only some of a deck's copies of one name (a name lock holds the deck's whole need of it, SHARE-090).
- Tokens (not cards, [[Physical Copies Across Decks]] fact 13; rejected by DECK-026). *(v0.3 also left
  runes out of scope, SPEC-009; since v0.4 they are counted, SHARE-006.)*
