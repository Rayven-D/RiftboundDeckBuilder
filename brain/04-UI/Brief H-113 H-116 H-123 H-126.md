# Brief H-113 / H-116 / H-123 / H-126: dialogs lift off the page, notices wait for the user, the header buttons line up, and the hero note matches the mode

Four small fixes, one branch (`loop/H-113-misc-polish`). The only new string is RJ's "Free account" (H-126).
Keep everything that's already built: the H-139 focus ring, H-101 phone snack-bar offset, H-102 danger
variant, the sign-in, sign-out and delete dialogs (H-104…H-143), the account menu (H-141/H-142/H-110) and the
gate panel (H-144). Contrast below is WCAG 2.x relative luminance, measured from the token hex values.

## H-113: dialog surface and dialog text use the app tokens

**Problem.** `--mat-sys-surface` maps to `--color-bg` (`styles.scss` :root), and Material's dialog container uses
`surface`. So in dark mode a dialog is the same `#1b1f24` as the page, and only the scrim separates them
(review #11). Material also colours dialog body text with `on-surface-variant` (light `#3c4947`, dark `#bbcac6`,
both tinted teal), not `--color-text`. That's close to `--color-text-muted`, so in every dialog the main line and
the muted `.note` look alike (found in H-143).

1. **New token `--color-surface-dialog`** in `styles.scss`, next to the other surfaces:
   - dark (`:root`): `var(--color-surface-raised)` = `#2d343c`
   - light (the `prefers-color-scheme: light` block): `var(--color-surface)` = `#ffffff`

   **Why light isn't `--color-surface-raised`:** in light mode raised (`#e9edf1`) is *darker* than the page
   (`#f4f6f8`), so a raised dialog would look sunk and grey. White is the lifted surface in light mode, and it
   matches the Collection card dialog (`.card-dialog-panel` already uses `--color-surface`). This goes slightly
   beyond the row text ("raised"), which only described dark mode. The review allowed either option for light.
2. **One `mat.dialog-overrides` block** in the same place as the existing `mat.menu-overrides` /
   `mat.button-overrides` (the global theme block):
   ```scss
   @include mat.dialog-overrides((
     container-color: var(--color-surface-dialog),
     subhead-color: var(--color-text),          // title
     supporting-text-color: var(--color-text),  // body text (was on-surface-variant)
   ));
   ```
   The title, body `<p>` and the warning use `--color-text`. Lines with a class keep their own colour:
   `.note` / `.explanation.note` muted, `.error` danger, the import dialog's muted lines. Don't change the
   dialog font or size.
3. **Keep `.card-dialog-panel`.** Its pane-level `--mat-dialog-container-color: var(--color-surface)` sits closer
   than the global override, so it still wins. Don't change the card dialog in this item.
4. **Dividers inside dialogs (dark).** `--color-border` `#343c45` on the raised surface is only 1.13:1, so the
   import dialog's summary line and issue-list rules (`import-dialog.scss`, `border-top` / `border-bottom`) would
   disappear. Add `--color-border-dialog` (dark `#434c56`, light `#d3d9e0`, the same as today's light border) and
   set `.mat-mdc-dialog-surface { --color-border: var(--color-border-dialog); }` once in `styles.scss`. Why: it
   gives the same weight a hairline has on the page (1.44 on raised vs 1.48 for border on bg), with no change to
   component files. Light stays at 1.42 on white.
5. **Optional lift:** `container-elevation-shadow: var(--shadow-lift)` in the same override. It's cheap and helps
   a little in dark mode. Leave it out if Material's M3 dialog already draws a shadow you can see.

## H-116: notices close on their own only when they confirm something

**Problem.** `SyncService.notify()` opens every sync notice with `duration: 8000`, except session-lost (review
#14). Errors ("Couldn't sync…") and instructions (the 5-minute delete step) disappear before anyone can read or
act on them, which fails WCAG 2.2.1. Material's default `politeness` is already `'polite'` and its default
`duration` is `0` (stays open), so errors are never announced as assertive.

**Three kinds.** Pass the kind with each message, e.g. `notify(message, kind)` in `EngineDeps` with
`kind: 'success' | 'info' | 'error'`, set where the engine calls it. Don't map from the message text: the
lock-short and clock messages are built at run time. **Unknown or missing kind = `info`** (stays open), so a new
message can never close on its own by accident.

| Kind | `duration` | `politeness` | Action | Messages (as in `MESSAGES` and the engine) |
|---|---|---|---|---|
| `success` | `6000` | `'polite'` | `OK` | `deletedOwn` "Your account and its data were deleted."; `deleteNotDone` "Your account wasn't deleted." (the result of the user's own Cancel); "You're signed in." (SYNC-006) once it's built |
| `info` (instructions and events) | none (stays until OK) | `'polite'` | `OK` | `sessionLost`; `reauthNeeded`; `accountDeleted`; `halfDeleted`; `paused`; "'…' (locked) is now N cards short."; "'…' changed on another device while it was locked."; the device-clock warning |
| `error` | none (stays until OK) | `'assertive'` | `OK` (or `Try again`) | `signInFailed`; `offline` (an action was refused); `writeFailed`; `tooLarge`; `unreadable`; `invalid`; `deleteIncomplete` |

- `AccountMenu.runDelete()`'s `deleteIncomplete` notice with **Try again** is an `error`. Add
  `politeness: 'assertive'` to it explicitly. It already has no duration.
- **Don't move focus into a notice.** The OK button stays reachable with Tab, as it is today. The new rule only
  removes the timer.
- **Not in this item:** the Collection page's two notices ("This card is no longer in your collection.", the CSV
  export line) already use 6 s with no action, as `success`. Leave them alone. If someone later builds a shared
  notice helper, note that **COLL-054** needs a Remove-card **Undo** notice to stay up for at least 8 s, so Undo
  must not fall under the 6 s rule.
- **H-101 offset unaffected:** it's pure CSS on the container.

**Tests (Vitest, spy on `MatSnackBar.open`):** one per kind through `SyncService.notify` checking `duration`
(`6000` / `undefined` or `0`), `politeness` and the `OK` label. One check that an unclassified message stays
open and is polite. One check that `runDelete`'s failure notice is assertive with `Try again`. Engine tests:
each listed `MESSAGES` key is sent with the kind in the table.

**Spec check.** SPEC-010 sets **no** duration or politeness for any notice. It only says "shows …" and, for
SYNC-096, that the failure notice has **Try again**. So nothing in this table contradicts the spec. **Spec question
for `spec-writer` (doc-only, not blocking):** should SPEC-010 record the three notice kinds as a design rule (6 s
for confirmations, errors and instructions stay until OK, assertive only for errors), so the validator tests the
spec and not only this brief? Related finding, **not part of this item:** SYNC-074 says "A notice lists each such
deck", but the engine sends one notice per short deck. Material shows one snack bar at a time, so only the last
deck is still on screen. That needs its own builder row (one combined notice).

## H-123: header Sign in / Account is 44 px and clearly bounded

**Problem.** The outlined Sign in / Account trigger (`account-menu.ts`) uses Material's 40 px height, while the
tabs and Import are 44 px, so it sits off the row (review #20). Its outline is the global
`outlined-outline-color: var(--color-border)`: in light mode that's `#d3d9e0` on `#f4f6f8`, only 1.31:1.

1. **Give both trigger buttons a class** (e.g. `header-account`) and, in `AccountMenu`'s component styles, set:
   ```scss
   .header-account {
     --mat-button-outlined-container-height: 44px;
     --mat-button-outlined-outline-color: var(--color-border-strong);
   }
   ```
   This is the same pattern `.import-action` uses for its 44 px. Scope it to the header only, and don't change the
   global outlined border in this item (see the open choice below).
2. **`--color-border-strong` is the existing control-edge token (H-086).** No new token. Measured against the
   header background:

   | Header state | Dark `#727d89` | Light `#7f8994` |
   |---|---|---|
   | At rest (bg) | 3.95 | 3.28 |
   | Scrolled (surface 86% over bg) | 3.54 | 3.52 |

   Everything is ≥ 3:1 (1.4.11). The label stays `--color-text`. The hover state layer stays Material's.
3. **Don't touch** the corner radius (6 px, `corner-full`), the text, the H-139 focus ring (2 px outside: 44 + 8 =
   52 px fits in the 64 px header and the 56 px phone header), or `display: contents` on the host.
4. **Phone (< 40rem):** the button stays at the header's right edge (wordmark pushes), now 44 px tall in the 56 px
   header, so the tap target is ≥ 44 px.

**Open choice for RJ (not in this item):** use `--color-border-strong` for *all* outlined buttons (home "Import a
deck" / "See winning decks", the dialogs' "Sign out anyway" / "Upload file", Import "Import another"). In light
mode they have the same faint edge. It's a one-line change to the global `mat.button-overrides`, but it changes
the home hero RJ approved, so it needs his OK.
