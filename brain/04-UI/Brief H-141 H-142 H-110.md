# Brief H-141 / H-142 / H-110: who is signed in, what a stuck deletion offers, and grouping

**Problem.** The signed-in menu (`web/src/app/core/sync/account-menu.ts`) is one undivided list with no identity (#8).
During an unfinished deletion it still offers Sync now and adds a pending count to the deletion error (#9). Its one
divider (H-102) is Material's teal-tinted `surface-variant`, not `--color-border` ([[Validation H-102]] note).
All strings are SYNC-003 / SYNC-084 / SYNC-096 text, written exactly. No new strings.

## Decisions
1. **Identity line (H-141).** First child of the panel: `<p class="menu-text identity" [id]="identityId">Signed in as
   <span class="address">{{ email }}</span></p>`, only `@if` `currentEmail()` is not null (then the menu starts with
   the status, AC 53). Plain `<p>`: no `mat-menu-item`, no `tabindex`, no `role`. "Signed in as" is
   `--color-text-muted`, the address is `--color-text` at the same weight (400). Why: the address is the thing to check,
   so it gets the stronger colour, and the muted status below reads as secondary. No bold: weight 500 belongs to the
   item labels. `.address { overflow-wrap: anywhere; }`, so the full address wraps and is never cut off.
2. **Shared text style `.menu-text`** (replaces `.status`, used by identity, status and offline lines): `margin: 0;
   padding: var(--space-1) var(--space-3); max-width: 20rem; font-size: var(--font-size-sm); line-height: 1.4;
   color: var(--color-text-muted)`. Why: 12px inline padding = Material's `menu-item-leading-spacing`, so text lines
   up with the item labels (today `--space-4` puts them 4px off), and 14px matches the item labels. The panel's own
   280px cap still applies. Group padding: the first line gets `padding-top: var(--space-2)` and the last line of the
   group `padding-bottom: var(--space-2)`, so with one line it stays 8px top and bottom, as now.
3. **Screen readers.** Keep `role="status" aria-live="polite"` on the status. Add
   `<mat-menu aria-describedby="{identityId} {statusId}">` (identity id only when the line is rendered), so opening the
   menu reads who is signed in and the state before the first item. Ids from a counter, like `errorId`.
4. **Deletion state (H-142).** While `sync.deletion()` is set: the status is exactly "Some data couldn't be deleted.
   Try again." (no pending count; the engine's `statusLine()` does this, not the template); the retry item reads
   **Try deleting again**; the snack-bar action in `runDelete()` stays `'Try again'`; Sync now is **not rendered**
   (`@if`/`@else`, not `[disabled]`). Sync now and the count return when `deletion()` clears.
5. **Error status gets the `.error` treatment, not colour alone.** When `status().kind === 'error'` (the deletion
   line and the plain "Couldn't sync…" line), render `<app-icon name="error" />` (decorative, `aria-hidden`) before the
   text, `display: flex; gap: var(--space-1); align-items: flex-start`, colour `--color-danger` (on the panel
   surface 6.51 dark / 7.07 light, H-102). Why: it is a real failure next to its fix, and the dialogs already show
   failures this way (H-106). The words carry the meaning, so colour is extra. Other kinds stay muted, no icon.
6. **Groups (H-110).** Top to bottom: [identity + status + offline] / [Try deleting again, Cancel deletion] **or**
   [Sync now] / [Sign out] / [Delete account and data]. The two middle groups never show together, so the template is
   fixed and can't double or trail a divider:
   ```
   identity? · status · offline?
   <mat-divider />
   @if (deletion) { Try deleting again · Cancel deletion? } @else { Sync now }
   <mat-divider />
   Sign out
   <mat-divider />
   Delete account and data (danger)
   ```
   Exactly 3 dividers in every state. Never one first or last.
7. **Offline line moves into the status group**, directly under the status, same `.menu-text` (muted, no icon). Why:
   it explains the disabled items before the user reaches them. At the very end it reads as a note on Delete only.
   It duplicates the Offline status ("Offline · changes are saved on this device") but SYNC-003/081 require both. Not
   changed here (spec-writer can merge them later).
8. **Divider colour: global menu token.** In `styles.scss`, inside the `html` block after `theme-overrides`:
   `@include mat.menu-overrides((divider-color: var(--color-border)));`. Root cause: the menu styles
   `.mat-mdc-menu-panel .mat-divider` with `--mat-menu-divider-color`, which defaults to `--mat-sys-surface-variant`,
   not to `outline-variant` (which we already map to `--color-border`). Do **not** remap `--mat-sys-surface-variant`
   (other components use it). `--color-border` is defined in both `:root` blocks, so dark `#343c45` and light
   `#d3d9e0` follow the theme with no extra rule. It is decorative, so 1.4.11 doesn't apply (it's the app's hairline
   everywhere). **Spacing:** keep Material's 8px above and below each divider (= `--space-2`). No override.

```

 Signed in as rj@example.com       Signed in as rj@example.com

 ─────────────────────────         ─────────────────────────
 Sync now                          Try deleting again
 ─────────────────────────         Cancel deletion
 Sign out                          ─────────────────────────
 ─────────────────────────         Sign out
 Delete account and data           ─────────────────────────
                                   Delete account and data
```

**Out of scope:** the header status badge (#18), a Settings link, Sign out dialog text. **Must keep:** H-102 danger
item and colour, H-139 inset ring, 48px items, `busy()` disabling, no address in any store or log (SYNC-100).

## Accept (ui-engineer Playwright pass, 1440 and 375, dark and light)
Reach the states with the dev hook from [[Validation H-102]] (`sync.status.set(...)`, and the deletion signal), never
a real deletion.
- Normal: identity line, status, 3 dividers, Sync now / Sign out / Delete. Null email: no identity line, menu starts
  with the status. A 60-character address wraps inside the panel with no horizontal scroll at 375.
- Deletion (AC 54): status text exact with no count, icon and `--color-danger` (≥ 4.5:1 measured), items Try deleting
  again, Cancel deletion (when allowed), Sign out, Delete; no Sync now in the DOM; snack-bar action reads "Try again".
- Offline: "You're offline." is right under the status, above the first divider; nothing after Delete.
- Dividers: computed `border-top-color` = `--color-border` in both themes; 8px above and below; never doubled, first
  or last in any state.
- Keyboard: open with Enter/Space, the first item gets H-139's inset ring; ArrowDown/Up move only between items (the
  text lines and separators are skipped); the snapshot shows the panel described by identity + status.
- Text lines start at the same x as item labels. Console clean. Tests for ACs 43, 53, 54 pass.
