# Brief H-144 / H-114 / H-115: one gate panel, the same box as Tournaments' empty state

**Problem.** `SignInPanel` (`web/src/app/core/sync/sign-in-panel.ts`) is a second, tighter copy of
`app-empty-state` (`--space-5` padding instead of `--space-7`, no deck mark, its own action row) (#12). The
running state has no progress cue (#13). The copy has per-page headings and old lines (#15, #16). **RJ confirmed on
2026-11-24: no panel heading in any state.** The page header's h1 names the page.

## Strings (exact, SYNC-009 / SYNC-086 v0.10). Remove `GATE_HEADINGS`.
| State | Line | Action |
|---|---|---|
| signed out | `Sign in or create an account to start keeping track of your collections and decks` (**no full stop**, RJ verbatim) | Sign in |
| session lost | `You've been signed out. Sign in again to continue.` | Sign in |
| first sync running | `Getting your collection and decks from your account…` (single `…` character) | progress bar |
| first sync failed | `Couldn't get your collection and decks. Check your connection and try again.` | Try again |

## Decisions
1. **Make `app-empty-state`'s heading optional.** `heading` becomes `input<string>('')`. Render the `<h2>` only
   `@if (heading())`, and set `[attr.aria-label]="heading() || null"`, so a panel without a heading has no name.
   Tournaments (`heading` + `message`) stays exactly as it is now.
2. **Every gate state is an `app-empty-state`** with no heading, the line as `message`, and the button or bar
   projected into `.actions`. That gives it the same padding (`--space-7` / `--space-4`), dashed border, surface,
   mark, gaps and centred action row as Tournaments. `.gate` and its styles go away. `SignInPanel` keeps its
   `@switch` and only picks the message, role and projected content.
3. **The deck mark shows in all four states.** It's decorative (`aria-hidden`, as now). If it's always there, the box
   keeps the same height and shape when running changes to failed or back, so the page doesn't jump. The failed
   state needs no error icon: the wording and `role="alert"` carry it, and the panel stays calm (Direction A).
4. **Line role.** Add an optional `messageRole` input to `app-empty-state` (`'status' | 'alert' | null`, default
   `null`) and bind it as `[attr.role]` on the `<p>`. Running uses `status`, failed uses `alert`, and signed out and
   session lost use none (the line is there when the page loads, so nothing needs announcing).
5. **No landmark, no name.** The `<section>` without an accessible name is not a region landmark, which is right
   here: it sits inside `<main>` under the page h1, and an `aria-label` would just repeat the h1 or the line.
   **Drop `aria-busy="true"`** from the running state. On an ancestor of the `role="status"` line, some screen
   readers hold the announcement until busy clears, which here means it's never read.
6. **Message styling in `app-empty-state`, applies to both uses:** `text-wrap: balance` on the `<p>` (this fixes the
   "or / decks" break at 375). **When there is no heading, the line is the primary text:** use `--color-text`, not
   muted, at the base size. Tournaments keeps a muted message under its heading. Trade-off: the two boxes differ in
   that one colour, but a muted only line reads as secondary text with nothing above it.
7. **Progress bar (running state only), a CSS bar, not `mat-progress-bar`.** It's lighter, adds no module, and the
   global reduced-motion rule (`styles.scss`: duration 0.01ms, iteration count 1) would leave Material's
   indeterminate bar parked off-screen as an empty track. Spec: a `div` track `width: min(16rem, 100%)`,
   `height: 4px`, `border-radius: 999px`, `background: var(--color-border)`, `overflow: hidden`. Inside it, a segment
   40% wide, `background: var(--color-accent)`, sliding left to right (`translateX(-100%)` → `translateX(250%)`),
   `1.4s var(--ease-out) infinite`. **Reduced motion:** `animation: none` and the segment resting centred
   (`translateX(75%)`), so it still reads as "in progress", not as an empty or full bar. **`aria-hidden="true"`** on
   the bar: the `role="status"` line already says what's happening, and a `progressbar` with no value only adds noise.
8. **Buttons, unchanged except that they are projected.** Sign in is `matButton="filled"` with
   `aria-haspopup="dialog"`, and focus goes back to it when the dialog closes (H-125). Try again is
   `matButton="filled"`.
9. **Focus around Try again.** Clicking it removes the button (running state). Give the empty-state `<section>`
   `tabindex="-1"` in the gate (`outline: none`, it isn't a control) and focus it with `afterNextRender` after a
   retry, so focus doesn't drop to `body`. If it fails again, move focus to the new Try again button. If it succeeds,
   the page content replaces the panel. Don't move focus then, as on any first render.
10. **Page header spacing.** The panel follows the page header with the header's own bottom margin, the same as
    Tournaments' header-to-empty-state gap. Don't add a margin of your own.

**Code:** update `gated-pages.spec.ts` (it still asserts `app-sign-in-panel h2` and the old line) and name the tests
by AC (26, 27, 46, 47, 57). After the build, `web/src` must contain none of: "Sign in to see your collection",
"Sign in to see your decks", "Sign in to import cards and decks", "You need a free account", "Sign in again to see
them". Update the Sign-in gate row in [[UI Index]].

**Out of scope:** the Sign in dialog, the header and account menu, Tournaments' deck controls. **Must keep:** H-139
focus ring on the buttons, H-125 focus return, the page header on every gated page, local-only mode (no panel anywhere).

## Accept (ui-engineer Playwright pass, 1440 and 375, dark and light)
Reach the states with the dev hooks and fakes from [[Validation H-102]] (signed out, `sessionLostUid`, a slow or
rejected first sync).
- **AC 46 / 26:** `/collection`, `/decks`, `/decks/<id>` and `/import` each show the page header, then the panel with
  the deck mark, the signed-out line exactly (no full stop) in `--color-text`, and Sign in. There is **no `h2`** in
  `app-sign-in-panel`, and the section has no `aria-label` or `role="region"`.
- **AC 27 / 57:** in a lost session, the same four pages show "You've been signed out. Sign in again to continue."
- **AC 47 / 57 running:** `/import` shows the line with `role="status"`, no `aria-busy` on the panel, and the bar
  (16rem at 1440, no wider than the content at 375, `aria-hidden`) moving. **Reduced motion:** two screenshots 1s
  apart are identical, and the segment rests centred (not empty, not full).
- **Failed:** the line has `role="alert"`, Try again is there, and the mark is still there. The box height differs
  from the running state by no more than the bar/button difference. Keyboard: Tab reaches Try again, Enter goes to
  running with focus on the panel (not `body`), and a second failure puts focus on Try again.
- **H-114 side by side:** the gate and `/tournaments`' empty state have the same padding, border, mark size and
  action gap (computed styles equal). At 375 the line wraps balanced (no single word on the last line), with no
  horizontal scroll. Contrast: line ≥ 4.5:1 in both themes. Focus ring on Sign in is unclipped. Console clean.
