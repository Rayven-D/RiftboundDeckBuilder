## Failures
1. **H-230 (spec-writer, P1):** TEST-050 says Remove empties the collection and "the marker goes with it", but the marker is `catalogVersion`, a top-level field that the push writes with every collection write (`top` includes `catalogVersion`). The spec never says what `catalogVersion` an emptied collection holds. If it stays `test-data-5000`, TEST-010 (banner iff `catalogVersion` starts with `test-data-`) still shows the banner on the empty collection and TEST-030 still calls it test data, so AC 9 ("empty state returns") and AC 13 contradict the marker rule. Expected: a stated post-Remove value (and TEST-012 / TEST-030 behaviour on an empty collection) plus an AC.
2. **H-231 (spec-writer, P1):** the write counts are given as a fixed 6 (1 account update included) in TEST section, the Summary, ACs 4 and 10 and the H-205 Accept ("expect 6 / 0"). In the code the account update happens only on a build change, so a normal Load is 5 writes, and Remove's three deck writes are pushed only after the 10 s deck-delete Undo window (SYNC-035, `DECK_UNDO_MS`), which the spec does not mention for TEST-051. Expected: "5 (6 on the first push after a build change)", the Undo-window delay stated, and the H-205 / AC wording changed to a range so the builder's recorded number does not look like a miss.
