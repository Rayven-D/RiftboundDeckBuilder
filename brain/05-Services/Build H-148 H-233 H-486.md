## H-148: one notice for every short locked deck (SYNC-074)
- `SyncEngine.afterMerge` used to send one `info` notice per short locked deck. Material shows one snack bar at a
  time, so only the last one stayed. It now sends **one** `info` notice built by `lockedShortfallNotice(list)`
  (exported from `web/src/app/shared/sync/sync-engine.ts`), or none when the list is empty.
- **Wording chosen (RJ to confirm):** the spec gives only the per-deck sentence, so the combined notice is the
  spec sentence once per deck, joined by a space, in the hook's order. This is the same form the import Undo
  notice already uses (SHARE-034). Example:
  "'Draven Aggro' (locked) is now 2 cards short. 'Kennen Tempo' (locked) is now 1 card short."
  One deck gives exactly the AC 13 text: "'Kennen Tempo' (locked) is now 1 card short."
- **H-075 coordination:** H-075 is still `todo`, so the `shortfalls` hook is still not wired in the app (`SyncService`
  passes none), and this change only shows up once H-075 lands. A local WIP branch `loop/accounts-sync-work`
  (6d089f7, not validated) rewrites `afterMerge` and still sends one notice per deck. When H-075 is rebuilt or
  rebased, keep the single `lockedShortfallNotice(...)` call. The deck order then comes from SPEC-008
  `lockedShortfalls` (lock order).
- Test seam: `Device` (`shared/sync/testing/device.ts`) takes an optional `shortfalls` hook.

## H-233: Replace import over test data (TEST-033, AC 12)
- `CollectionImport.commit` calls `removeTestDecks(stores, now)` on **every Replace**, right after the collection
  write. Without test decks it does nothing, and it also clears a stray test deck (TEST-034). If the collection
  write fails, nothing is removed. If the removal fails, the import still stands and a stray deck is removed by the
  next Replace or Remove. An Add never removes decks, because TEST-032 blocks Add first.
- **Gap found and fixed:** while test data is stored, `CardData.loadCatalog()` returns the generated catalog
  (TEST-024, `catalogVersion: 'generated'`), so the import resolved names against invented cards and would have
  written `'generated'` as the new collection's `catalogVersion`, not the real one. New `CardData.loadApiCatalog()`
  always returns the `/api` catalog (own cache, cleared by `reload()`), and `CollectionImport.prepare` uses it.
  Other pages still use `loadCatalog()` unchanged.
- **Behaviour chosen:** the Replace confirmation's IMP-050a "(locked) will be N cards short" warnings leave out the
  test decks, because they go in the same commit. The confirmation is otherwise unchanged (TEST-033). Removed test
  cards show by their card key (the generated names lowercased), because names resolve against the real catalog.
- Undo of such a Replace restores the test collection (and so the banner) but not the test decks. Remove test data
  still clears it. This is not covered by the spec, so it is left as is. Flag it if it should restore the decks too.

## H-486: flaky `npm test` (unhandled Firebase `initializeAuth` errors from `app.spec.ts`)
- **Cause:** the Angular unit-test builder runs Vitest with `isolate: false` (its default), so spec files in one
  worker share one jsdom and its `localStorage`. `App` renders the deferred account control, whose `SyncService`
  starts the engine. If another file had left a sync log with `sessionExpected: true` (written by an engine after
  that file's `localStorage.clear()`), the engine loaded the **real** `SYNC_ADAPTERS` (`createFirebaseAdapters`),
  and `initializeAuth` failed in jsdom with unhandled rejections. Whether it happened depended on which files shared
  the worker, about 1 run in 3. Reproduced on purpose: seeding that log before `app.spec.ts` gives 13 unhandled
  errors with the same stack (`firebase-adapters.ts:97`).
- **Fix:** `app.spec.ts` clears `localStorage` before each test and provides a stub `SYNC_ADAPTERS` (`FakeAuth` +
  `FakeRemote`) in all four `TestBed` setups. A new test, "H-486 a leaked sync log with sessionExpected starts the
  engine on the stub adapters, not on Firebase", seeds the leaked log and checks that the stub is what gets loaded.
